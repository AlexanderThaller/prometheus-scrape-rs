= Performance improvements, round 3
:toc:
:source-highlighter: rouge

Tracking document for the third optimization round (2026-07-12, branch
`perf-improvements-2`). Round 2 (see `perf-improvements-1.adoc`) shipped
1.25x CPU on the training workload plus the memory work (CompactString
labels, compressed retained bodies, managedFields stripping) and is live
in production. Per [the user's priority] memory savings outrank CPU
savings; the Bytes-labels bar (+20% live CPU) remains the revert
criterion.

== What is new this round: live remote-write profiling

The training workload never exercised the network path. This round adds a
*live harness* that captures the full pipeline including remote-write 2.0
against the local Mimir:

* `python3 -m http.server 18000` serving `pgo-corpus/*.prom` as scrape
  bodies;
* an agent config with one job per corpus file × two replica-labeled
  targets (14 targets, ~30.6k tracked series), `scrape_interval: 4s`
  (2s overruns the local Mimir ingest limit: 1.3k retries and queue-full
  drops in 2 minutes — 4s runs clean);
* `remote_write` to `http://127.0.0.1:9009/api/v1/push` with
  `protobuf_message: io.prometheus.write.v2.Request` and
  `X-Scope-OrgID: anonymous` — matching the production protocol, which
  turned out to be RW2.0 already.

Config lives in the session scratchpad (`live-test.yml`); regenerate with
the snippet above. Verified end-to-end: batches accepted by Mimir, zero
retries/failures during the measurement window.

== Candidates

=== 1. Single-pass RW2.0 encoder with cheap interning — status: *done, −22% total live CPU*

Measured 2026-07-12/13 on the live harness (120 s perf @ 4999 Hz, identical
load, NAS Mimir accepting all batches, zero retries):

* baseline (prost + SipHash interning): 9048 samples, encode path ~23%;
* single-pass with borrowed-key Fx map: 8171 samples (−10% total) — but
  `intern` at 21.5%: the map *probe* (SIMD group scan + cache misses on
  ~670k lookups/round), not the hash, dominates;
* plus previous-series memoization: *7075 samples (−22% total CPU)*,
  `intern` down to 5.9% — consecutive series share label names and most
  values, so an equal-string compare against the previous series reuses
  the ref without touching the map. Reuse cannot change interning order,
  so output stays byte-identical (parity-tested, including a corpus-scale
  batch).

Absolute encode-path cost fell ~47%. The per-series `labels_refs` Vecs,
owned symbol `String`s and the SipHash map are gone; `V2Scratch` holds the
one reusable flat ref buffer.

Target: the ~23% live CPU block plus its allocations. Files:
`src/model.rs`, `src/remote_write.rs`.

* Extend the hand-rolled encoder to `WriteRequestV2`: write the symbols
  and series directly into the output buffer in one pass — the
  intermediate `WriteRequestV2` struct, its `Vec<String>` symbols table
  and `Vec<u32>` labels_refs disappear entirely.
* Replace the `HashMap<String, u32>` interning (SipHash + double
  `to_owned` per unique string) with an FNV/FxHash-style map keyed on
  borrowed `&str` from the batch. No new dependency needed — an FNV u64
  over the string plus a small open-addressing table, or `HashMap<&str,
  u32, BuildHasherDefault<FxLikeHasher>>` with a hand-rolled hasher.
* Parity test: byte-equality against the current `encode_v2` +
  prost-derive output for a corpus batch.

=== 2. Fetch scrape bodies without the lossy copy — status: open

Target: ~4.3% live CPU + one full-body allocation/copy per scrape.
File: `src/scrape.rs` (`fetch`).

`response.text()` runs encoding detection and `String::from_utf8_lossy`,
which copies the whole body. Switch to `response.bytes()` +
`std::str::from_utf8` (fast SIMD validation, zero copy; reject invalid
UTF-8 as a scrape error like Prometheus does). The retained-body
compression consumes `&[u8]` anyway.

=== 3. Faster series hashing in the staleness tracker — status: open

Target: part of the 12.6% `scrape_loop` block. File: `src/scrape.rs`.

`hash_labels` runs byte-at-a-time FNV-1a over every label of every series
each scrape (~1 byte/cycle). The hashes are only ever compared within the
process lifetime, so any stable-within-process 64-bit hash qualifies:
process 8-byte chunks with wrapping multiplies (FxHash-style) or fold the
existing FNV over `u64` words. No new dependency required.

=== 4. Single-sample series in the internal model — status: open

Target: ~20% of live allocations (one `vec![Sample]` per series per
scrape) plus 24 bytes per series of `Vec` overhead in every batch.
Files: `src/model.rs`, `src/parser.rs`, `src/scrape.rs`,
`src/remote_write.rs`.

The pipeline creates exactly one sample per series per scrape (the
parser emits one `TimeSeries` per sample line; staleness markers are
single-sample too). Replace `samples: Vec<Sample>` with `sample: Sample`
in the *internal* series type; the hand-rolled encoders write it as a
repeated field of one on the wire (wire-format identical). The prost
derives move to test-only shadow types for decode/parity. Combines
naturally with candidate 1 since the v2 encoder is being rewritten
anyway.

=== 5. Deferred / rejected

* *zstd for retained bodies* — rejected in round 2 (C dependency in the
  musl build); unchanged.
* *Further parser work* — parse is down to 7% live; diminishing returns.
* *`sort_labels`* — 2% live; revisit only if rounds above land short.
